# 元服务性能对比

面向 HarmonyOS / OpenHarmony 元服务的 Windows 桌面测试工具。填写改造前后两个包名，一键依次测试，生成可离线查看的 HTML 对比报告。

[下载最新版本](https://github.com/yezikanwo555-droid/harmony-service-impact/releases/latest) · [详细使用说明](docs/使用说明.txt) · [网络模拟说明](docs/网络环境说明.txt)

## 能做什么

- 冷启动、热启动、CPU、PSS 内存、APP/HAP 包文件大小对比。
- 实时 CPU / PSS / 可读缓存目录曲线，支持时间窗口、联动读数、键盘逐点查看和暂停画面；采集不受暂停查看影响。
- 双包曲线同图：改造前蓝色实线、改造后橙色虚线；上传 / 下载速率与累计流量消耗也支持对比，并加入离线报告。
- 自动读取系统存储页中的应用缓存，记录测试前后大小与增长量，不修改正式包。
- 读取当前前台应用包名；可配置次数、采样间隔、日志目录。
- 受控随机 Monkey，可设置时间、事件上限、间隔和种子。
- Monkey 默认开启应用内模式：禁用随机返回，每次操作后检查，跳出自动拉回；拉回失败停止并保存日志。可取消勾选恢复普通模式。
- Monkey 自动保存系统 HiLog 和本轮目标应用的崩溃 / AppFreeze 日志，报告区分系统证据确认与疑似无响应。
- Wi-Fi、蜂窝、断网及内置代理模拟；包含较慢、较快、2G/3G/4G/5G 等预设，测试结束恢复网络设置。
- 公开 GitHub Release 检查更新、展示说明、下载并校验 SHA256；无需 GitHub 登录。

## 开始使用

1. 下载 Release 的 `ServiceImpact-版本-windows-x64.exe`，放在可写目录直接运行，无需解压或安装 Python；ZIP 供需要随包说明的用户选择。
2. 电脑安装 HarmonyOS SDK 的 hdc；手机开启开发者调试、授权电脑并保持解锁亮屏。可在“设备与高级设置”指定 hdc 路径和设备。
3. 将两个版本以不同包名安装到同一设备，在“测试工作台”填写包名，或分别打开应用后点击“获取当前应用包名”。
4. 设置测试方式、次数、网络环境和保存目录。比较包体时，分别选择对应的 APP/HAP 文件。
5. 点击“开始一键对比”。结果在“版本对比”页显示，完整报告自动生成。

同包名覆盖安装的两个版本，需要更换版本后分别采集、导入结果，不能一键并存比较。工具不负责安装应用。

## 测量边界

冷启动采用 `aa start -W` 的 TotalTime（首帧口径），需要设备 API 20+ 支持，不以命令执行时间替代。冷启动保留数据与缓存。CPU 按整机容量计，内存使用同 UID 可见进程的 PSS 合计。包体为所选文件大小，并非安装占用。

系统缓存和自动代理页面主要适配 HarmonyOS 7 中文设置布局；其他版本需要验证。锁屏、权限不足或布局变化会报告失败，缺失值不计为零。系统页面缓存是前后快照，并非持续实时监控。

内置模拟仅作用于遵循系统 HTTP 代理的流量，HTTPS 保持加密；不覆盖 UDP/QUIC 和绕过代理的请求。延迟及失败按新连接模拟，**不是 IP 层丢包**；3G/5G 名称是测试预设，不改变真实通信制式。代理统计不能按包名归因。蜂窝模式需可用 SIM 卡，尚需在实际目标设备验证。

停止、正常退出及普通异常会尝试恢复网络。设备锁屏、断线或进程被强制结束时，解锁连接原设备后，在网络设置中点击“恢复上次环境”。

流量通过 `hidumper --net PID` 读取目标应用 UID 的接收/发送字节计数，扣除首次有效基线。显示上传、下载、总消耗及相邻有效采样间隔的平均速率。包括该 UID 全部接口，不是运营商账单流量，可能包含代理/回环；共享 UID 不能按包名拆分。启动前无运行进程时无法取得基线，仅从资源阶段首次有效读取后累计，报告明确标为覆盖不完整；不把历史流量当成本轮消耗，也不使用整机总流量替代。正式包无需修改，设备须允许该诊断命令。

本工具关注性能、流量和缓存影响，不验证埋点内容；最终无影响结论仍需业务功能回归及多轮对照采样。Monkey 请使用测试账号。

Monkey 系统日志保存在各组 `logs/diagnostics/system_hilog.log`；故障证据为 `fault_001.log` 等，`summary.json` 记录归属、时间与覆盖状态。正式包无需修改，使用系统已有诊断权限。按起始故障列表、目标 UID、进程名及设备时间窗口筛选，并核对日志头部；系统上报的 JS / Native 崩溃或 AppFreeze 才标为已确认。命令超时仅标为疑似无响应，也可能是 USB / 设备 / 工具故障。自动拉回或画面不变不等于崩溃或卡死。

HiLog 只覆盖系统当前允许输出的日志，可能包含其他应用或业务信息，仅保存在本机。系统日志上限 100 MiB，故障日志每份 20 MiB、每轮最多 20 份；触及上限会提示不完整。结束后等待 2 秒再查询故障，延迟更久的系统上报可能遗漏；日志不存在、权限不足或空日志不代表没有异常。日志采集与故障查询有开销，停止后还会执行有限的导出收尾。完整日志留在各组结果目录，报告仅展示摘要与文件名。

## 更新与本地数据

“实时监控”默认显示曲线，可切换最近 60 秒、最近 5 分钟或全部数据。悬停或聚焦图表后使用左右方向键查看读数，Home/End 跳到首尾点。切换“采样明细”可核对原始值和错误原因。CPU 固定为整机容量 0–100%，内存与缓存分别使用从零开始的 MiB 坐标轴；缺失读数断开，不填零、不平滑。长序列按屏幕像素聚合绘制，保留区间极值，原始记录仍完整保存。

“暂停查看”仅冻结曲线；顶部最新值、后台采集和采样明细继续更新。点击“继续实时”返回最新窗口。双包视图在进入下一组时保留另一组，只替换本组旧数据。可选择“资源占用”或“网络流量”；按各组资源阶段开始后的秒数对齐，较短组结束后不补线。系统存储页缓存显示测试前、测试后和增长量，不连接成连续曲线。

“关于与更新”支持手动/启动时检查正式版本，点击“一键更新并重启”后自动下载、校验、解包到暂存区、等待旧程序退出、替换并重启，无需手动解压。原 EXE 旁保留 `.previous-标识` 备份；替换或启动调用失败会尝试回滚，后续运行异常可手动使用备份。测试或网络恢复尚未结束时不能更新。需要原程序目录可写，源码运行不替换 Python。

v2.1 及更早版本没有自动替换逻辑，首次升级请直接下载 v2.2+ 独立 EXE，关闭旧版后运行；之后使用工具内一键更新。用户设置与结果目录保留。

设置保存在 `%LOCALAPPDATA%\ServiceImpact\impact_settings.json`，更新下载在其 `updates` 子目录，测试结果保存在自选目录。首次从旧版升级时，可以把旧 `impact_settings.json` 放在新 EXE 旁；尚无新版设置时会读取并迁移。GitHub 仓库只包含源码、合成测试和说明，不包含业务包、实测日志或凭据。检查更新仅请求 Release 信息，不上传采集结果。

## 源码运行与构建

使用 Windows x64、Python 3.14（包含 tkinter）。运行时仅依赖标准库，设备采集另需 hdc。

```powershell
python src/impact_app.py
$env:PYTHONPATH = "$PWD/src"
python -m unittest discover -s tests -p 'test_*.py' -v
python -m pip install -r requirements-build.txt
python scripts/build_release.py
```

构建脚本生成 `dist/ServiceImpact-版本-windows-x64.zip`、同名独立 `.exe` 和 `dist/SHA256SUMS.txt`。开发测试不需要手机，使用合成数据和模拟设备响应。真实设备兼容性需另行检查。

## 发布新版

修改 `src/app_meta.py` 的 VERSION，更新 `CHANGELOG.md`，运行测试并构建。将代码推送到仓库，在 GitHub 创建同版本正式 Release（如 `v2.0.1`），上传 ZIP 和 SHA256SUMS。待 ZIP 上传完整后发布 Release。更新客户端读取 GitHub 资产的 SHA256 digest；没有有效校验信息时会拒绝下载。

代码结构：`src/impact_app.py` 为控制器，`desktop_view.py` 为界面，`impact_engine.py` 为采集与报告，`comparison_job.py` 为两组调度，`network_session.py` 为网络恢复，`update_service.py` 为更新校验。

图表交互设计参考 [UI UX Pro Max skill](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) 的时序图、数据表替代视图、键盘操作和可见焦点规范。图表实现使用 Tkinter Canvas，不引入前端框架或第三方绘图库。
